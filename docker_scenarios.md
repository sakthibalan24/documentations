# Docker Interview Preparation: Scenario-Based Questions

## Section 1: Docker Fundamentals

1.  Your Spring Boot application works on your laptop but fails on
    another developer's machine. How would you solve this?
2.  You have built one Spring Boot image, but your application needs
    three instances to handle requests.
3.  What happens when you stop and remove a container?
4.  You need to check whether your container is running. How do you
    investigate it?
5.  What is the difference between an image, a container, and a Dockerfile?
6.  How does Docker leverage Linux namespaces and cgroups under the hood?

## Section 2: Dockerfile and Image Building

1.  Your Docker image is very large. How would you reduce its size?
2.  Every small code change makes your Docker build slow. What would you
    do?
3.  What is the difference between `CMD` and `ENTRYPOINT`?
4.  Your Docker build fails because the JAR file cannot be found. How do
    you fix it?
5.  What is the difference between `COPY` and `ADD`?
6.  What is a Docker build context, and why does `.dockerignore` matter?
7.  What are the trade-offs between using Alpine, Debian-slim, and Distroless images (e.g., glibc vs. musl compatibility, debugging capabilities)?
8.  How do BuildKit cache mounts (`--mount=type=cache`) and secret mounts (`--mount=type=secret`) improve build speed and build security?
9.  Why should you avoid running `apt-get update` and `apt-get install` in separate `RUN` instructions?

## Section 3: Ports and Networking

1.  Your container is running, but you cannot access the application
    from your browser. What will you check?
2.  Explain bridge networking using a real-time example.
3.  Why does `localhost` fail when one container connects to another?
4.  Explain Docker port mapping versus `EXPOSE`.
5.  What are bridge, host, none, and overlay networks?
6.  Containers on a user-defined bridge network can communicate by container name, but on the default bridge network they cannot. Why?
7.  Your container experiences intermittent connection timeouts or packet drops over cloud VPC or VPN connections. How does MTU mismatch cause this, and how do you fix it?
8.  How does Docker's internal embedded DNS server (`127.0.0.11`) handle name resolution and DNS caching?

## Section 4: Volumes and Persistent Data

1.  Your PostgreSQL container is deleted. How can you prevent database
    data loss?
2.  What is the difference between a named volume and a bind mount?
3.  What is the difference between a volume and the container writable
    layer?
4.  A non-root container user gets a "Permission Denied" error when writing to a bind-mounted host folder. How do you resolve UID/GID mismatch issues?
5.  When should you use `tmpfs` mounts instead of Docker volumes or bind mounts?
6.  How do you back up, restore, or migrate data stored inside a Docker named volume?

## Section 5: Environment Variables, Configuration, and Security

1.  How do you pass environment-specific configuration to Docker?
2.  A developer hardcoded a database password in a Dockerfile. What is
    the problem?
3.  How do you secure a Docker container?
4.  Why is passing database passwords via `docker run -e PASSWORD=...` considered insecure in production, and what are the alternatives?
5.  How do you run a container with a read-only root filesystem (`--read-only`), and how do you handle temporary files generated by your application?
6.  What are Linux Capabilities (`--cap-drop=ALL`, `--cap-add=...`) and how do they help enforce the principle of least privilege?
7.  How do you run Docker in rootless mode, and what are its security benefits and limitations?

## Section 6: Docker Compose and Multi-Container Applications

1.  Your application requires Spring Boot, PostgreSQL, and Redis. How
    would you run all three?
2.  What is the difference between `docker compose up` and
    `docker compose down`?
3.  Your backend starts before the database is ready and fails. How
    would you fix it? (e.g., `depends_on` with `condition: service_healthy`)
4.  Can Docker Compose replace Kubernetes?
5.  How do you override configurations for development, staging, and production using multiple compose files (`docker-compose.override.yml`)?
6.  How do you manage network isolation between tiers (e.g., frontend cannot talk directly to the database) in Docker Compose?

## Section 7: Docker Registries and Image Versioning

1.  You built an image locally. How do you deploy it on another machine?
2.  Why should you avoid using `latest` as your production image tag?
3.  Docker image pull fails with an authentication error. What will you
    check?
4.  How do image digest tags (e.g., `my-app@sha256:...`) guarantee true immutability compared to semantic version tags?
5.  How do you configure and use image vulnerability scanners (e.g., Trivy, Grype, Docker Scout) in your container registry?

## Section 8: Docker Logging, Monitoring, and Debugging

1.  Your application is running inside a container, but you cannot find
    its logs.
2.  Your Docker container consumes too much CPU or memory. How do you
    investigate?
3.  A container keeps restarting. How do you identify the root cause?
4.  What are Docker restart policies?
5.  A host disk is 100% full because container JSON logs were never rotated. How do you prevent and remediate this with `log-driver` options?
6.  What is the difference between exit codes: 0, 1, 137 (OOMKilled), 139 (Segmentation fault), and 143 (SIGTERM)?
7.  How do you use `docker debug`, `docker exec`, and ephemeral debug containers when troubleshooting a stripped-down Distroless container that has no shell or package manager?

## Section 9: Health Checks and Graceful Shutdown

1.  How do you know whether a Docker container's application is actually
    healthy?
2.  Your Spring Boot application is terminated while processing
    requests. How do you handle graceful shutdown?
3.  Why does `docker stop` take exactly 10 seconds before forcibly killing your application?
4.  What is the PID 1 problem in Docker containers, and how does using an init system (like `tini` or `docker run --init`) fix signal forwarding and zombie process reaping?

## Section 10: Docker and CI/CD

1.  How would you automate Docker deployment through a CI/CD pipeline?
2.  A deployment works in testing but fails in production. How would
    Docker help you investigate?
3.  What are the security implications of mounting `/var/run/docker.sock` inside a CI/CD agent container (Docker-out-of-Docker vs. Docker-in-Docker vs. Kaniko/Buildah)?
4.  How do you optimize Docker build cache in CI pipelines where runners are ephemeral?

## Section 11: Advanced Docker Interview Scenarios

1.  What is the difference between Docker Engine and a container
    runtime (e.g., containerd, runc, CRI-O)?
2.  What is a dangling image, and how do you clean up unused Docker
    resources?
3.  How do you troubleshoot Docker DNS or network connectivity problems?
4.  How do you pass build-time arguments versus runtime configuration?
5.  What happens when a Docker container uses too many file descriptors
    or processes?
6.  Why should you use immutable image versions in production?
7.  What is the "live-restore" setting in Docker daemon, and why is it critical for zero-downtime Docker daemon upgrades?

## Section 12: Additional Docker Concepts You Should Not Miss

1.  What happens if the Docker daemon stops?
2.  What is the difference between Docker Swarm and Kubernetes?
3.  How would you build a multi-architecture Docker image (e.g., amd64 and arm64) using `docker buildx`?
4.  How would you prevent a container from running as root?
5.  What is the difference between Docker container health and
    application availability?

## Section 13: Memory, CPU Limits, and Runtime Behavior (JVM / Node.js)

1.  Your Java/Spring Boot container gets killed by the host kernel (Exit Code 137) even though JVM heap usage looks low. What happened (Metaspace, native memory, thread stacks, cgroups v1 vs v2)?
2.  How do JVM flags `-XX:+UseContainerSupport`, `-XX:MaxRAMPercentage`, and `-XX:InitialRAMPercentage` optimize memory allocation in Docker containers?
3.  How does CPU throttling occur when you configure `--cpus="1.5"` or `cpu-quota`, and how does it degrade application latency?
4.  Why does Node.js or Java sometimes detect 32 host CPU cores instead of the container's configured limit, and how does this lead to thread pool misconfigurations?

## Section 14: Storage Drivers and Disk Space Troubleshooting

1.  The host directory `/var/lib/docker/overlay2` is taking up 95% of disk space. How do you diagnose whether the cause is unpruned layers, huge container writable layers, or dangling volumes?
2.  What is the difference between copy-on-write (CoW) in the container writable layer and direct I/O in a Docker volume? Why is running heavy database writes on a container writable layer detrimental to performance?
